# How-To Guide: Verifying Container Image Provenance (SLSA v1.0)

**Module:** `@atlas/security/supply-chain`  
**Standard:** SLSA (Supply-chain Levels for Software Artifacts) v1.0  
**Registry:** GitHub Container Registry (`ghcr.io`)  
**Target Images:** `atlas-frontend`, `atlas-backend`, `atlas-worker`  

---

## 1. Overview

Atlas-Logistics container images published to GitHub Container Registry (GHCR) include cryptographically signed build provenance attestations generated via GitHub Actions and Sigstore Cosign.

Each attestation cryptographically binds:
- The immutable container image digest (`sha256:...`).
- The canonical GitHub repository (`xpallares1987-ai/Atlas-Logistics`).
- The exact git commit SHA and ref (`refs/heads/main` or `refs/tags/v*`).
- The workflow execution definition (`.github/workflows/ci.yml` or `.github/workflows/docker-build.yml`).
- The trusted OIDC issuer (`https://token.actions.githubusercontent.com`).

---

## 2. Prerequisites

To verify container provenance attestations on any workstation:
1. Install the [GitHub CLI (`gh`)](https://cli.github.com/) (version 2.49.0 or later).
2. Authenticate with GitHub CLI:
   ```bash
   gh auth login
   ```
3. Docker or Podman (optional, if pulling images locally).

---

## 3. Verification Commands

### 3.1. Strict Repository & Signer Workflow Verification (Recommended)

To enforce strict cryptographic identity verification, specify both the exact repository (`--repo`) and the authorized signer workflow (`--signer-workflow`):

#### Frontend Container Image
```bash
gh attestation verify oci://ghcr.io/xpallares1987-ai/atlas-frontend:latest \
  --repo xpallares1987-ai/Atlas-Logistics \
  --signer-workflow xpallares1987-ai/Atlas-Logistics/.github/workflows/ci.yml \
  --format json
```

#### Backend API Container Image
```bash
gh attestation verify oci://ghcr.io/xpallares1987-ai/atlas-backend:latest \
  --repo xpallares1987-ai/Atlas-Logistics \
  --signer-workflow xpallares1987-ai/Atlas-Logistics/.github/workflows/ci.yml \
  --format json
```

#### Async Worker Container Image
```bash
gh attestation verify oci://ghcr.io/xpallares1987-ai/atlas-worker:latest \
  --repo xpallares1987-ai/Atlas-Logistics \
  --signer-workflow xpallares1987-ai/Atlas-Logistics/.github/workflows/ci.yml \
  --format json
```

### 3.2. Verification by Immutable OCI Digest

For production deployments, verify using the exact, immutable sha256 digest rather than mutable floating tags:

```bash
gh attestation verify oci://ghcr.io/xpallares1987-ai/atlas-backend@sha256:<IMAGE_DIGEST> \
  --repo xpallares1987-ai/Atlas-Logistics \
  --signer-workflow xpallares1987-ai/Atlas-Logistics/.github/workflows/ci.yml
```

## 4. Expected Output & Verification Criteria

A successful verification output displays the cryptographic signing certificate and SLSA statement:

```text
Loaded digest sha256:84f6d6... for oci://ghcr.io/xpallares1987-ai/atlas-frontend:latest
Loaded 1 attestation from GitHub
✓ Verification succeeded!

[Attestation summary]
Repository: xpallares1987-ai/Atlas-Logistics
Workflow:   xpallares1987-ai/Atlas-Logistics/.github/workflows/ci.yml@refs/heads/main
Commit:     0d3d0c9 (or current release commit)
Signer:     GitHub Actions (OIDC - https://token.actions.githubusercontent.com)
```

If the image was modified, tampered with, built from an untrusted fork, or generated by an unapproved workflow, `gh attestation verify` fails with an explicit non-zero exit code and halts execution.

---

## 5. Automated CI/CD Enforcement & Verification Gate

SLSA provenance is not merely generated; it is **strictly enforced** as a blocking gate before any deployment:

1. **Generation**: [ci.yml](../../.github/workflows/ci.yml) generates SLSA build provenance attestations during the `build-images` job.
2. **Blocking Verification Gate (`verify-provenance`)**:
   - Executes after `build-images` completes.
   - Verifies all 3 container images (`atlas-frontend`, `atlas-backend`, `atlas-worker`) against the repository and signing workflow.
   - Exports machine-readable attestation payloads to `provenance-evidence/`.
   - Halts the entire pipeline if any verification check fails.
3. **Evidence Archival**:
   - The verified JSON attestations are archived as GitHub Actions workflow artifacts (`slsa-provenance-evidence`) with 90-day retention for audit compliance without polluting Git repository history.
4. **Deployment Gate (`deploy-notification`)**:
   - Requires `verify-provenance` to pass before publishing the final deployment confirmation.
